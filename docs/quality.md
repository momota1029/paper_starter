# 品質の移植と確認範囲

原型の `doc` 環境の品質機構を分野横断に移した。ここでいう移植は
個別の原稿や研究室固有の文体を複製することではなく、失敗を検出して直し、
確認し直す仕組みの継承である。

| 原型の機構 | このスターターでの実装 |
| --- | --- |
| AGENTS → skill → rules | [入口](../AGENTS.md)、[skill](../.agents/skills/paper-writing/SKILL.md)、[rules](../rules/INDEX.md) |
| 記号・型・範囲、前提と適用の橋渡し | [基本論理](../rules/logical-writing.md)、[監査](../rules/argument-audit.md) |
| 未検証資料と計算・検証記録の分離 | inbox、evidence.md、claims.json |
| 近い論文の構成・圧縮・文体を実物から学ぶ | [prose](../rules/prose.md)、corpus.md |
| 外部入力の積極的な確認、初出帰属、厳しい著者条件の継承 | [品質契約 Q01–Q03](../rules/quality-contract.md)、役別のcoverage記録 |
| Spec / Generate / Audit の独立性 | [review-loop](../rules/review-loop.md)、[役割](../rules/reviewer-roles.md) |
| リスク別 L0–L3、担当数、差分と依存範囲 | [review-loop](../rules/review-loop.md) |
| 初読の理解を修正前後で確かめる | 固定した目標、前方読み、観測の照合、新しい読者 |
| 引用の支持と書誌の整合性を別に確認 | [sources](../rules/sources.md) |
| 忠実な翻訳と理解用ノートの区別 | [companions](../rules/companions.md) |
| 組版、自己完結した提出物、著者の通読 | [release](../rules/release.md) |
| 役割ごとの実際のモデル設定 | [.codex/agents](agents.md) |
| 対象版とレビューの一致 | [CLI](../tools/README.md)のsnapshot / verify / record / readiness |
| 一片ずつの本文提示と実観測の保持 | [補助の順次読者CLI](reader-runner.md)。隔離・理解の自動認定ではない |

基本論理は分野横断で維持する。数学固有の対象、特定の記号、数式のない要旨、
固定の証明末尾、著者順、決まった言語の四成果物、個人のGit運用は共通の強制にしない。
それらのうち必要なものはプロジェクトの契約で明示する。
実証、質的・人文、レビュー固有の確認は [分野別契約](../rules/research-profiles.md) で補う。

## 何を確かめたと言えるか

1. 機械検査は設定・ファイル・記録・ハッシュ・拒否条件を確かめる。
2. 独立した規則監査は、移植漏れや矛盾、実装の欠陥を点検する。
3. 実際のAI評価は、与えたケースで何を発見・修正・理解したかを示す。
4. 人間の読解と専門的な検証は、本人の理解と研究の妥当性を確かめる。

これらを互いの代わりにしない。実行した結果は [検証記録](validation.md) に記す。
未実行のfixtureや設定ファイルの存在を、成功した実評価と数えない。
AIの専門知識が読者の不足知識を補ってしまう限界も残る。

この移植だけから「全分野の完成論文が原型と同品質」とは実証できない。
初期基準は、原型の重要な機構を維持し、既知の失敗を検出し、必要な
独立確認・人間の通読が未完了なら完了と宣言しないことである。
実運用で著者が確認した改善例は、公開可能な範囲だけを新たな回帰評価にする。

2026-10-02に [原型との対比較](equivalence.md) を実行した。二組の短い数学論文の
内容評価では劣化は検出されなかったが、読者目標の確認証拠と規則上の残課題により、
全体の同等性の認定には至っていない。点数の一致を同等性の証明には使わない。

その後の依頼で、[契約差の補強と別素材による検査](hardening.md)を実行した。
既知の不足を規則・役割・記録検査に反映し、修正ループの実観測を保存している。
