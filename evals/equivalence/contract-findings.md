# 規則の同等性監査

原型側の設計を終えた read-only 担当が、原稿比較とは別に両環境の規則を読んだ。
この担当はスターターの実装者ではない。以下は規則上の差であり、生成原稿で
実際に生じた誤りと同一視しない。根拠箇所は統合担当も確認した。
原型の非公開ファイルや個人パスはここへ複製しない。

## 維持されている機構

- 主語と述語、指示先、量化、普通の変数の型・範囲、推論・適用の橋渡し、
  段落の根拠、節の依存は [L01–L13](../../rules/logical-writing.md) と
  [A01–A10](../../rules/argument-audit.md) に残っている。
- 正しさと理解の独立した終了条件、順次読解、前方の区切りでの理解を後方で
  代用しないこと、新しい読者、差分の依存範囲、変更のない引き直しの禁止は
  [review-loop](../../rules/review-loop.md) に明示されている。
- 引用が主張を支えるかと、書誌・引用キー・資料の同一性の確認は別担当である。
- Luna/Sol の役割分担と推論設定は実ファイルにある。原型のwriterがLuna、
  スターターがSolである差は明示的な変更であり、設定の欠落ではない。

## 同等と認定する前に残る三点

### C1 — 外部知識の確認結果を、合格時にも列挙する義務

原型の `mm-space-referee.toml` は、読者の既有知識の外から導入する入力ごとに
「定義」「必要な命題の仮定と結論」「今回への適用」を本文の位置とともに示す。
欠落がなくても、この三つの所在の一覧を合格の根拠として要求する。

スターターは [L11](../../rules/logical-writing.md) と
[A05](../../rules/argument-audit.md) に適用条件の点検を残すが、
[argument_reviewer](../../.codex/agents/argument_reviewer.toml) の報告契約には、
問題がないとした入力まで網羅的に列挙する義務がない。
原型の「指摘がない」以上の積極的な確認証拠は、同じ強さで必須化されていない。

### C2 — 分野契約が求める初出時の帰属を照合する索引

原型の `math-prose.md` S11 は、借用した概念と初出時の引用を索引で照合する。
スターターの [sources](../../rules/sources.md) と L10 は帰属を要求し、
A04 は定義・初出を索引化するが、初出時の帰属欄は明示されていない。

全分野に数学と同じ引用位置を強制しないことは妥当である。一方、ある論文の
分野契約で初出帰属が必要な場合に、それを検査項目として確実に復元する手順は弱い。

### C3 — 参考論文への拘束力と、既存の著者承認条件

原型の `prose-paper-en.md` と `agent-orchestration.md` は、近接論文の構成を
強い設計条件とし、逸脱には著者判断を要求する。独立した事前の文体・構成調査もある。
スターターは実物の近接論文、所在、構成、説明量、文体と採らない慣習を要求するが、
プロジェクトごとの「厳守事項／強い参考／弱い参考」と、既存の逸脱承認条件を
明示して引き継ぐ仕組みは同じ強さではない。

特定研究室の作法を全分野へ強制しないのは意図した一般化である。ただし既存の
厳しい分野契約を移す際、単なる参考例へ弱めないための手順は補う余地がある。

## 今回の判断

C1–C3 は同等性の残課題として開いたままにする。今回は確認の依頼なので、
評価結果を良く見せるために本番のスキルや規則を後から書き換えていない。
修正する場合は個別の数学作法の全面強制ではなく、各プロジェクトの読者・分野契約に
応じた検査と証拠の出力義務として実装し、今回使っていない素材で再評価する。

また、初読の自動隔離には実行上の失敗があった。
[手法の変更と限界](method-deviations.md)を参照する。この失敗は今回のホストでの
観測であり、「原型の標準起動なら成功する」という比較結果ではない。
