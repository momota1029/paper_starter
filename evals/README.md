# 文章・ワークフローの評価

[cases.json](cases.json) は独自に作成した小規模な架空の素材で、実在の研究結果を
示すものではない。理論、実証、人文学、レビュー、翻訳について、問題のある
原稿と保持すべき短い対照例を含む。ツールの回帰テストとは別に評価する。

## 実行

1. 評価の統合担当が対象と実行資源を決める。作業先は `.paper-local/evals/` または
   使い捨ての別フォルダにし、本物の研究へ書き込まない。
2. 新しい執筆担当へ依頼文、対象素材、根拠、該当するスキルと規則を渡す。
   採点基準や想定修正は渡さない。修正、保留した結論、用いた根拠を保存する。
3. 別の専門担当が、根拠との一致、必要な修正、保留、良い対照例の保持を調べる。
   検出できたかと適切に直したかを別に採点する。
4. 読みやすさを測る場合は、さらに別の初読者へ中立な版名と原稿だけを渡す。
   元原稿と修正版は別の読者に割り当て、前から一片ずつ読み、次の片を開く前に
   何を理解したかを記録する。初読者は修正文を書かない。
5. 期待した理解と観測を照合する。必要なら修正を一括し、新しい読者で再確認する。
   出力を増やしただけ、文体が変わっただけの改稿を改善と数えない。

## 判定

採点の観点は、主張の射程、条件・量化・帰属、証拠から結論への橋渡し、
定義と参照、読者の理解、不要な変更の有無。特定の言い回しの一致で採点しない。
良い対照例に対する不要な修正、架空の根拠や分析の追加は失敗として数える。

ワークフローも逆境条件で確かめる。古い版、先読み、期待回答の漏洩、
同じ読者の再利用、未実施の確認、予算終了、未解決の必須目標を成功扱いしない。
review-only の依頼では原稿を編集しない。

結果には実行日時、担当と実際に確認できたモデル、入力と出力、
成功・失敗・未実行を残す。同じ素材で規則を調整した後は、未使用の別素材で
再評価する。小規模な架空例の成功を実際の完成論文の品質保証に一般化しない。

## 原型との対比較の記録

短文修正とは別に、[二題の全長記事の対比較](equivalence/README.md)を実行した。
事前基準、初稿、読者の実観測、未確認事項を保持している。
結論は [同等性報告](../docs/equivalence.md) を参照する。

そこで見つかった契約差を補強した後の、未使用素材による
[三分野の検査と実読者起動](contract-transfer/README.md)は別実験として記録した。
前の同等性判定を後から合格に変更してはいない。
