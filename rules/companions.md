# 翻訳と理解用ノート

正本の言語はプロジェクトで決める。翻訳やノートは依頼された場合に作る。

## 忠実な翻訳

情報と役割を保つ。節の対応、主張、条件、量化、数値、図表、留保、
帰属、引用位置を正本へ一意にたどれるようにする。
自然な語順、文の分割・結合、指示対象の最小限の明確化はよい。
説明の付け足し、段落の削除、主張の強化・弱化、独立した構成の作り直しはしない。

訳文で論理的な欠陥に気づいたら、正本で確認して修正・再検証し、影響箇所を同期する。
訳文だけを正しい別論文にしない。翻訳の意味の忠実さと訳文としての読みやすさは
別に調べる。定理数やラベル数の一致だけでは歴史説明や限定の脱落を検出できない。

## 理解用ノート

想定読者の前提に合わせ、結果の全体像 → なぜそう考えるか → 正確な主張 →
論証の見取り図 → 難所 → 必要な道具、という深まりを設計する。
これは固定の章名ではない。分野と読者に合う順序を採用する。
最初から全前提を列挙して結果を後回しにせず、道具を導入する直前に用途を説明する。

各段階で何を新しく理解できたかを確認する。単なる要約の繰り返しでは深まらない。
具体例は条件を試す、結論を実現する、誤解を区別するなどの役割を持つ。
ノートは根拠を新たに認証する文書ではなく、著者や読者が原稿へ入るための文書である。
AIが著者の理解を `understood` と宣言しない。
