# 資料から原稿へ

レビューの起動と終了は [review-loop](review-loop.md) を先に読む。
この手順は新規論文・大きな改稿用で、誤字修正に全工程を要求しない。

## 1. 受け入れと検証

外部の会話、断片、AIの提案、手計算は `inbox/` に保持する。
採用する資料とその出所を特定し、`writing/<slug>/evidence.md` に、
対象、条件、方法、証明／分析／解釈、依存する出典、未解決点を記す。
実行した計算と提案だけの計算を区別する。元資料を完成原稿で上書きしない。

主要主張と危険な依存だけを `claims.json` に記録する。分類は
`original / cited / routine / unresolved`、検証状態は `pending / verified / contradicted`。
`original` は原稿自身で立証するという役割で、世界初を証明するラベルではない。
「既知と思うが出典不明」は `unresolved`。探索範囲を記録し、見つからなかった
ことだけから新規性を断定しない。要旨・導入の主要結論と台帳を照合する。

分野ごとに [research-profiles](research-profiles.md) を適用する。
原著の本文、データ、解析、引用箇所が未確認なら、その依存する結論を保留する。
確認不能でも原稿の骨組みや既に確かな部分は進められる。

## 2. 設計

`corpus.md` に近い論文の観察をまとめ、`design.md` に次を記す。

- 主たる問い、主張、読者、前提知識、言語、論文種別、投稿先の制約。
- 導入・各節の役割と依存順、主張と根拠を置く場所、重要な限界。
- 保持すべき条件・留保・帰属と、圧縮／付録化／不採用にする部分および理由。
- 自然な区切りごとに読者が説明できるべきこと。必須と任意を区別する。
- 変更対象、固定する比較原稿、最大の修正範囲、必要な査読観点。

### 作る成果物を選ぶ

成果物の組は依頼と既存の契約から決め、`design.md` に選択した組、
各ファイルの役割・言語・パス、今回作らないものを記す。
数学・理論研究では、例えば次の組を選べる。

| 選択 | 作るもの |
| --- | --- |
| `pf/en` | 検証用の証明集と英語論文 |
| `pf/en/ja` | 証明集・英語論文と、その忠実な日本語訳 |
| `pf/en/lec` | 証明集・英語論文と、指定読者向けの理解用ノート |
| `pf/en/ja/lec` | 上の四成果物 |

`pf` は仮定、主張、証明と依存を追える検証用の文書、`en` は公開用の英語論文、
`ja` はその忠実な日本語訳、`lec` は理解用ノートを指す。
これは数学で使える組の例であり、全分野への固定形式ではない。
論文だけ、別言語の正本、既存の検証記録を使う構成も依頼に沿って選べる。

「pf/enだけ」と指定されたら、その組で進め、ja・lecを追加しない。
選ばなかった成果物は未完了の必須項目に数えず、それを作るための設計・
翻訳・講義用読者レビューも起動しない。選択済みなら重ねて聞かない。
指定がなければまず依頼された原稿と必要な検証記録の範囲で進め、
追加成果物が必要な判断点でのみ短く選択を聞く。四成果物を既定にしない。

証明集から新しく作る場合は `pf → en`、選択されたja・lecは確定した正本から
作る。lecはenから直接作ってよく、jaの作成を前提にしない。
後から組を追加・変更しても、依頼されていない既存ファイルを削除しない。
成果物を減らしても、選択された原稿の根拠・正しさ・必要なレビューは省略しない。

設計は利用者の意図と証拠で確定する。研究の主張、対象、倫理、著者責任など
実質的な未決事項だけを著者へ返す。既に許可された執筆の通常の編集判断まで
再承認を要求しない。設計者が自分の設計を独立監査したことにしない。

## 3. 執筆と検証

検証記録の発見順ではなく、読者の理解と論証の依存順に原稿を作る。
執筆者には確定した設計、根拠、採用した命名、関連規則だけを渡す。
空欄をもっともらしいデータ、引用、実験条件で埋めない。

一まとまりの改稿後にビルドする。原稿の全文または変更と依存範囲を実際に読み、
基本論理と分野の正確さ、出典、構成、初見の理解を分けて確認する。
指摘を照合して一つの修正指示にまとめ、修正後は新しい独立した確認へ回す。
ループの詳しい状態と停止条件は [review-loop](review-loop.md) が正本。

## 4. 派生成果物と引き渡し

原稿が確定してから必要な翻訳・理解用ノートを作る。英語から日本語に限らず、
指定された正本と言語の組を使う。依頼されたものだけを生成する。
下流で論理的欠陥を見つけたら正本の欠陥として戻し、直した依存範囲を同期する。
正本を変更する権限がなければ、差異と必要な修正を報告する。

投稿準備は [release](release.md) に従う。著者の理解と最終読解をAIが代行して
承認済みにしない。投稿用ファイルの準備は投稿・送信の許可ではない。
