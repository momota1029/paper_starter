# 作業領域

| 場所 | 役割 |
| --- | --- |
| `inbox/` | 未整理の資料・断片。検証済みとみなさない |
| `writing/<slug>/` | 一件の研究の正本、根拠、設計、メタデータ |
| `writing/<slug>/inbox/` | その研究に紐づく未処理資料 |
| `refs/` | 利用権限のある原典のローカル保存 |
| `index.bib` | 自分の文献管理用のローカル書誌データ |
| `output/<slug>/` | ビルド結果・共有準備用の生成物 |
| `.paper-local/` | 凍結した評価対象、実行結果、レビュー記録 |
| `index.md` | 入口となる目次 |
| `writing/index.md` | `meta.toml` から生成するローカル研究一覧 |

原稿、データ、文献と索引は初期状態でGit対象外。公開するスターターと
私的な研究を同じリポジトリへ不用意に混ぜない。Git除外は暗号化ではない。
共同研究用に追跡する場合は研究用の別リポジトリで対象を明示して設定する。

新規作成と索引更新は [tools](../tools/README.md) を使う。
slug は英小文字・数字とハイフン。タイトル、言語、profile、正本ファイル、
著者側のwriter識別子、読者、状態を `meta.toml` に記す。
状態は `draft / reviewing / revision / ready / submitted / published / archived`。
`ready` は記録上の状態であり、変更後も審査済みだと保証するフラグではない。

原稿の形式はMarkdownかTeXで始められる。既存の原稿はその形式を維持する。
外部へ単独で渡す生成物はslugを名前に含め、元の版を追跡できるようにする。
通常のビルドと固定した配布版を区別し、古い成果物を自動削除しない。

inboxの整理は依頼の範囲で行い、取り込み元と取り込み先を根拠記録に残す。
取り込み後の原資料は `inbox/processed/` 等へ保存する。未処理フラグを消すために
資料を捨てない。ツールは自動で資料を移動しない。

公表や投稿など外部で起きた状態は実際の通知または著者の情報で更新する。
原稿が出来たことから投稿済みを推定しない。共有・投稿・Git操作は依頼に従う。
