# 引き渡し前の確認

最終確認は [review-loop](review-loop.md) の全体確認モードで行う。
出力できたことと投稿可能であることを混同しない。

1. 現在の版について、主要な主張、根拠、引用、基本論理、構成、読者目標を確認する。
   過去の指摘を再照合し、未解決の重大な指摘と必要な読者目標を閉じる。
2. 著者が現行原稿を通読する。承認した版と実際の発言・記録を残す。
   AIが人間の読解や理解を完了済みにしてはならない。
3. 生成した全ページを見て、欠落、文字化け、数式、図表、改頁、参照、
   はみ出し、匿名査読時の著者情報を確認する。ビルドの終了コードだけで済ませない。
4. 別の一時ディレクトリに提出用ファイルだけを取り出し、必要な図、書誌、
   スタイルと依存が同梱され、作業環境外でもビルドできるか確認する。
   元の絶対パスや他の原稿の補助ファイルに依存させない。
5. 著者・順序・所属・謝辞・資金・利益相反・データ利用・AI利用申告等を、
   著者の判断と実際の投稿先の現行規定で照合する。分野で著者順を一律に決めない。
6. 最終レビュー後に対象が変わっていないことをハッシュで確認する。
   変わった場合は影響範囲の新しい確認が必要。古いパスにあるPDFを現行版とみなさない。

ツールの `readiness` は記録と版の機械検査であり、研究の正しさを認証しない。
実行していない査読、見ていないページ、承認のない著者判断を申告で埋めない。
完成したパッケージを送信・投稿するかどうかは利用者の指示に従う。
